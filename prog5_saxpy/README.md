# Program 5: BLAS `saxpy`（10 分）

> 本题考查**内存带宽瓶颈**：加核和加 SIMD 只能提升计算吞吐。当程序的瓶颈是从内存搬数据时，这些都帮不上忙。

## 背景：核心运算是什么

`saxpy` 是 BLAS 库里的标准操作，名字是 **S**ingle-precision **A**·**X** **P**lus **Y** 的缩写：

```
result[i] = scale * X[i] + Y[i]        // i = 0 .. N-1，N = 2000 万
```

每个元素：

- 读 `X[i]`、读 `Y[i]`、写 `result[i]`，共 3 × 4 = 12 字节的内存访问。
- 做 1 次乘法和 1 次加法，共 2 次浮点运算。

**算术强度**（每字节做多少次运算）= 2 / 12 ≈ 0.17 FLOP/byte，非常低。作为对比，现代 CPU 一个核每个周期能做几十次浮点运算，而内存每个周期只能送来几个字节。所以 saxpy 的速度几乎完全由**内存能多快地送数据**决定，这种程序叫 **memory-bound（访存受限）**。

三个数组每个 80 MB，共 240 MB，远大于 CPU 的缓存（几十 MB），所以每次运行都要从 DRAM 读。

## 运行

```bash
make
./saxpy
```

输出 ISPC 和 ISPC + tasks 两个版本的时间、带宽（GB/s）和 GFLOPS。

## 要做的事与提示

### 1. tasks 的加速比，以及能不能再提升

先估计：如果单核 ISPC 已经能用掉大部分内存带宽，再加 23 个核会怎样？

- 内存带宽是**整个芯片共享**的资源，不随核数增加。
- 用一个核时，瓶颈可能是这一个核能同时发出多少个内存请求（单核带宽有上限）；多核能同时发出更多请求，所以 tasks 版本还是会快一些，但远到不了核数倍。
- 回答“能否重写到接近线性加速”时，想想：瓶颈在哪个硬件上？代码改写能改变它吗？

### 2. 加分：为什么是 `4 * N * sizeof(float)`

代码只读 X、读 Y、写 result，看起来是 3 次访存。第 4 次来自**写**：

- CPU 写一个字节时，不是直接写进内存，而是写进缓存行（64 字节）。
- 如果这个缓存行不在缓存里，CPU 要先**把整行从内存读进来**（write-allocate，也叫 read-for-ownership），再修改它。
- 之后这行被换出缓存时，再**写回**内存。

所以写 `result` 实际上产生了一次读加一次写，总共 4 次。

### 3. 加分：显著提升性能

既然多出来的那次读是浪费的，有没有办法跳过它？关键词：

- **non-temporal store（流式写入）**：`_mm256_stream_ps`，ISPC 里是 `streaming_store`。数据直接写到内存，不经过缓存，也就不需要先读。
- 理论上从 4 次访存降到 3 次，最多快 4/3 ≈ 1.33 倍。

注意：`_mm256_stream_ps` 要求地址按 32 字节对齐，而 `main.cpp` 里的 `new float[N]` 只保证 16 字节对齐。你需要改成 `aligned_alloc(64, ...)`，或者先用普通写入处理开头不对齐的几个元素。写完之后要调用 `_mm_sfence()`，保证写入对其他核可见。

另一种思路是改变问题本身（例如把多次 saxpy 融合在一起，让数据在缓存里时多做几次运算），但这改变了题目，需要说明。

### 4. 估算你机器的内存带宽上限

`scripts/machine_info.sh` 不打印内存规格。在 Linux 原生系统上可以用 `sudo dmidecode -t memory | grep -i speed`；在 WSL2 上看不到，要到 Windows 任务管理器的“性能 → 内存”里看“速度”和插槽数。然后计算：

```
峰值带宽 = 内存速率 (MT/s) × 每次传输字节数 × 通道数
         = MT/s × 8 字节 × 通道数        // 每个 DDR 通道 64 位 = 8 字节
```

例：DDR5-5600 双通道 ≈ 5600 × 8 × 2 = 89.6 GB/s。实际能用到的通常只有峰值的 60% 到 80%。

把这个值和 `./saxpy` 报告的 GB/s 对比。注意程序报告的 GB/s 已经按 4 次访存计算了。

最后解释：`T` 个线程时 saxpy 的加速比为什么远低于 `T`。用一句话写出你的结论即可。

## 提示：这题不要想得太复杂

计算本身很简单，没有分支、没有依赖，工作量也完全均匀。本题的结论应该来自**带宽的数字**，而不是代码细节。
